# 0002. Модульный монолит, структура по контекстам

- Статус: Принято
- Дата: 2026-09-15

## Контекст

Бойлерплейт должен подходить проектам, которые начинаются как один сервис,
но могут вырасти до нескольких. Нужна структура, в которой границы видны и
проверяются автоматически, а не держатся на договорённостях.

## Решение

Код группируется по ограниченным контекстам:
`src/<Context>/{Domain,Application,Infrastructure,Presentation,Contract}`.

Контекст видит только `Shared` и `Contract` других контекстов. Правило
зависимостей между слоями и изоляция контекстов проверяются deptrac в двух
конфигурациях.

## Альтернативы

**Группировка по слоям** (`src/Domain/<Context>`). Проще выражается в
правилах deptrac, но размазывает контекст по нескольким деревьям: удаление
или выделение контекста в сервис становится дороже.

**Плоская структура Laravel** (`app/Models`, `app/Services`). Не выражает
границ вовсе.

## Последствия

- Каждый новый контекст добавляется в `deptrac.contexts.yaml` двумя
  правилами, включая исключение собственного `Contract` из слоя контекста.
- `Shared` рискует превратиться в свалку: туда попадают только технические
  абстракции и настоящие общие value objects.
- Контексты не связаны внешними ключами в базе; обмен идёт событиями, что
  требует проекций чужих данных там, где нужны выборки.
