# 0007. RFC 9457 для ошибок API

- Статус: Принято
- Дата: 2026-09-15

## Контекст

Нужен единый формат ошибок, пригодный и для человека, и для машины, и
достаточно расширяемый, чтобы описывать ошибки валидации по полям.

## Решение

Ошибки возвращаются как `application/problem+json` по RFC 9457. К
стандартным полям добавлены два расширения: `code` — стабильный машинный
код, и `traceId` — идентификатор трассировки.

Доменные и прикладные исключения не знают про HTTP; сопоставление делает
`ProblemMap`, который наполняет каждый контекст. Поиск идёт от точного класса
к родителям.

Успешные ответы отдаются без обёртки, коллекции — объектом с полями `items`
и `page`.

## Альтернативы

**JSON:API.** Полноценная спецификация, но избыточна для API, у которого
один основной клиент, и навязывает структуру ресурсов.

**Собственный формат** вида `{data, meta, errors}`. Ещё один нестандартный
конверт, который придётся описывать в документации.

## Последствия

- `code` становится частью контракта: фронтенд и локализация завязаны на
  него, а `title` и `detail` можно менять свободно.
- Каждое новое доменное исключение требует записи в `ProblemMap`, иначе
  превратится в 500. Базовые классы покрывают наследников автоматически.
- Клиентские ошибки исключены из отчётности, иначе каждый 404 попадал бы в
  алерты.
