# 0001. FrankenPHP + Octane как runtime

- Статус: Принято
- Дата: 2026-09-15

## Контекст

Изначально рассматривался NGINX Unit как более быстрая альтернатива php-fpm.
На момент выбора проект оказался архивирован: последний релиз вышел до
выхода PHP 8.5, новых версий не будет.

Требования: worker mode ради производительности, совместимость с PHP 8.5,
пригодность для Kubernetes, минимум движущихся частей в поде.

## Решение

FrankenPHP в worker mode через Laravel Octane. Один процесс на под, без
отдельного веб-сервера рядом.

## Альтернативы

**RoadRunner.** Go-сервер плюс пул отдельных PHP-процессов. Даёт изоляцию
сбоев: падение воркера не роняет сервер. Отклонён в пользу меньшей
сложности, но остаётся рабочим запасным вариантом — смена runtime затрагивает
только Dockerfile и конфигурацию, код не меняется.

**Swoole.** Реальный выигрыш даёт только конкурентный I/O внутри запроса, а
стандартные драйверы Laravel под это не заточены. Сложность не окупается.

**php-fpm.** Отброшен как исходная точка: нет worker mode, бутстрап на
каждый запрос.

## Последствия

- PHP собирается в ZTS-режиме, все расширения должны быть thread-safe.
- Segfault в расширении роняет весь процесс, а не один воркер.
- Приложение обязано быть stateless между запросами: никакого
  request-scoped состояния в singleton.
- В dev и в проде используется один и тот же runtime, различия только в
  настройках OPcache и наличии Xdebug.
