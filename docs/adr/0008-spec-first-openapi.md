# 0008. Spec-first OpenAPI с проверкой контракта в тестах

- Статус: Принято
- Дата: 2026-09-15

## Контекст

Контракт API нужен и фронтенду, и внешним потребителям. Генерация
спецификации из кода отражает то, что получилось, а не то, что задумано, и
расходится с реальностью незаметно.

## Решение

Спецификация пишется вручную в `docs/api/`, собирается Redocly в единый
бандл. Каждый HTTP-вызов из feature-тестов автоматически проверяется против
бандла: и запрос, и ответ.

Типизированный клиент для фронтенда генерируется из того же бандла;
расхождение ловится в CI.

Версия OpenAPI — 3.0.3, потому что валидатор для PHP не поддерживает 3.1.

## Альтернативы

**Генерация из кода** (Scramble, swagger-php). Меньше ручной работы, но
спецификация перестаёт быть проектным документом и не может опережать
реализацию.

**Без спецификации вовсе.** Клиент пишется руками, расхождения обнаруживаются
в рантайме.

## Последствия

- Новый эндпоинт нельзя добавить, не описав: тест упадёт на неизвестной
  операции.
- Изменение формата ответа ломает тесты раньше, чем клиентов.
- Фронтенд получает типы без ручной работы.
- Ограничения OpenAPI 3.0: `nullable: true` вместо union-типов.
