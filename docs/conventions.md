# Соглашения

Правила, выведенные из практики работы над этим проектом. Часть из них
закреплена инструментами (deptrac, PHPStan, тесты), часть приходится
соблюдать самостоятельно — такие отмечены отдельно.

## Домен

**Агрегаты не публикуют события сами.** Агрегат записывает событие через
`recordThat()`, репозиторий после сохранения вызывает `releaseEvents()` и
передаёт их коллектору. Это делает выброс событий частью транзакции команды,
а не побочным эффектом где-то в стороне.

**Восстановление из хранилища событий не записывает.** У агрегата два
статических конструктора: `register()`, `create()` и подобные — для новых
фактов в жизни агрегата, `restore()` — для подъёма из базы. Второй не
вызывает `recordThat()`.

**Репозиторий возвращает `?Aggregate`, а не бросает исключение.** «Не
найдено» — решение сценария, а не домена. К тому же доменный слой не может
зависеть от `Shared\Application\Exception\NotFound`.

**Домен не знает про фреймворк.** Ни `Illuminate\*`, ни `Carbon`. Время —
`DateTimeImmutable` и `Psr\Clock\ClockInterface`, передаваемый параметром.
Проверяется deptrac.

**Value objects валидируют себя в конструкторе** и бросают доменное
исключение. Приватный конструктор плюс именованные статические фабрики.

## Персистентность

**Один маппер на агрегат.** Преобразование между агрегатом и строками живёт
в мапперe, репозиторий отвечает только за запросы. Симметрично для всех
контекстов.

**Eloquent — только там, где его требует фреймворк.** `UserModel` нужен
Sanctum и auth-guard, поэтому существует. Refresh-токенам ничего такого не
нужно — там Query Builder и маппер. Модель без причины добавляет магию и
ничего не даёт.

**Чтение строк — через `Row`.** Он даёт типизированный доступ и внятную
ошибку с именем таблицы и колонки вместо `mixed` и падения где-то дальше.

```php
$data = Row::from($row, UsersTable::NAME);

return new UserView(
    $data->string('id'),
    $data->string('email'),
    $data->timestamp('registered_at'),
);
```

**Форматирование времени — через `Timestamp::format()`.** Литерал формата
не дублируется по файлам.

### Ловушки, на которых обожглись

**Точность timestamp.** У `timestampTz()` в Laravel точность по умолчанию
равна нулю, и Postgres округляет значение до секунды. Всегда указываем
явно:

```php
$table->timestampTz('registered_at', 6);
$table->timestampsTz(6);
```

Закреплено тестом `SchemaPrecisionTest`, который проверяет все колонки во
всех схемах.

**Каст даты в Eloquent — без параметра формата.** Точность задаётся
свойством `$dateFormat` модели. Если написать `'immutable_datetime:Y-m-d
H:i:s.uP'`, тип каста станет `immutable_custom_datetime`, значение не
приведётся к строке и уйдёт в биндинг объектом, а `Connection::
prepareBindings()` отформатирует его как `Y-m-d H:i:s` — доли секунды
потеряются.

```php
protected $dateFormat = 'Y-m-d H:i:s.uP';

protected function casts(): array
{
    return ['registered_at' => 'immutable_datetime'];
}
```

**Объекты вне таблиц в миграциях.** `migrate:fresh` удаляет таблицы, но не
функции, типы и схемы. Создавать их нужно идемпотентно, иначе повторный
прогон миграций падает:

```php
DB::statement('CREATE OR REPLACE FUNCTION ...');
DB::statement('CREATE SCHEMA IF NOT EXISTS identity');
```

**Порядок миграций для схем.** Схемы контекстов создаёт отдельная миграция
с датой раньше всех прочих (`0001_01_01_000000_create_context_schemas`).
Иначе на чистой базе таблица создаётся в несуществующей схеме.

**Пустой JSON-объект.** `json_encode([])` даёт `[]`, а не `{}`. Для
jsonb-колонок, где ожидается объект, нужен флаг:

```php
json_encode($metadata, JSON_THROW_ON_ERROR | JSON_FORCE_OBJECT)
```

Обратная сторона: `json_decode('{}', true)` возвращает пустой массив, а
`array_is_list([])` для него истинно. Отличать список от объекта нужно
только для непустых массивов.

## Контейнер и провайдеры

**Расширение карт — только в `register()`.** `CommandHandlerMap`,
`QueryHandlerMap`, `DomainEventListenerMap`, `DomainEventTranslatorMap`,
`IntegrationEventSubscriberMap`, `ProblemMap` — все они singleton. Вызов
`extend()` в `boot()` может не примениться, потому что карта уже разрешена.

Отказ при этом тихий: команда не найдёт обработчик только в рантайме, а
интеграционное событие пометится опубликованным и не доедет ни до одного
подписчика — без ошибок в логах.

В `boot()` остаётся то, чему нужен собранный контейнер: роуты, morph map,
консольные команды, лимитеры.

**Двойная регистрация запрещена.** Карты бросают исключение при попытке
зарегистрировать обработчик дважды. Лучше упасть при бутстрапе, чем молча
получить «последний победил».

**Никаких `assert()` для проверки контрактов.** В проде `zend.assertions`
выключены, и проверка исчезнет. Если класс из карты обязан реализовывать
интерфейс — явная проверка с `LogicException`.

## Octane

Приложение живёт между запросами, поэтому:

**Никакого request-scoped состояния в singleton.** Актор передаётся в
команды явным полем, а не через контейнер. Сервисы, которые обязаны
создаваться заново на каждый запрос, регистрируются через `scoped()`.

**Кеши внутри сервисов допустимы, если они не зависят от запроса.**
Например, кеш рефлексии в `AuthorizeCommandMiddleware` — он scoped и не
переживает запрос.

**Флаш телеметрии.** Фонового потока экспорта в PHP нет. Трассы
отправляются батчами по таймеру, метрики — только по явному `forceFlush()`,
который вызывает terminable middleware после ответа клиенту.

## Слои и границы

**Middleware, работающее с БД, моделями или внешними сервисами, —
инфраструктурное.** `ResolvePrincipal` тянет Eloquent-модели, поэтому живёт
в `Infrastructure/Http`, а не в `Presentation`. `AssignRequestId` работает
только с запросом и остаётся в `Presentation`.

**Когда deptrac запрещает связь — сначала проверь, туда ли положен класс.**
Ослабление правила маскирует проблему. Так `Principal` переехал из
`Identity\Contract` в `Shared\Domain\Access`: он описывает актора вообще, а
не деталь Identity, и Shared не должен зависеть от контекста.

**Константы, нужные двум слоям, живут в Application.** Ключ атрибута
запроса с `Principal` объявлен в `Shared\Application\Bus\ActorContext`:
писать его — работа инфраструктуры, читать — презентации.

## API

**Проверки — от точного класса к родителям.** `ProblemMap` ищет
соответствие по иерархии, поэтому наследники `NotFound`, `AccessDenied` и
`InvalidInput` получают статус автоматически. Отдельная запись нужна, только
когда требуется свой код или другой статус.

**Клиентские ошибки не логируются как инциденты.** Доменные исключения,
`NotFound`, `AccessDenied`, `Unauthenticated` и `InvalidInput` перечислены в
`dontReport`. Иначе каждый 404 попадал бы в алерты.

**Сообщения доменных исключений показываются клиенту.** Это осознанный
контракт: такие сообщения пишутся так, чтобы их можно было показать. Всё
немаппленное превращается в 500 без деталей.

**Ответ об ошибке аутентификации одинаков для всех причин.** «Нет такого
email» и «неверный пароль» неразличимы, иначе API становится оракулом для
проверки существования аккаунтов. По той же причине для несуществующего
пользователя выполняется проверка фиктивного хеша — чтобы время ответа не
отличалось.

## Наблюдаемость

**Имена спанов и метрик — такой же контракт, как поля API.** На них
завязаны дашборды и алерты, менять их нужно так же осторожно.

**Кардинальность метрик.** В атрибутах только значения с низкой
кардинальностью: шаблон роута, а не URL; имя команды, а не её содержимое.
Для незаматченных роутов ставится `unmatched`, подставлять путь нельзя.

**Cumulative temporality для метрик.** Экспортёр OTLP по умолчанию отдаёт
delta, а Prometheus на `/api/v1/otlp` принимает только cumulative и
отбрасывает delta молча: `forceFlush()` возвращает `true`, коллектор
отвечает 200, счётчик отклонённых точек остаётся нулевым. Задаётся явно:

```php
new MetricExporter($transport, Temporality::CUMULATIVE)
```

## Тесты

**Feature-тесты проверяют контракт автоматически.** Каждый HTTP-вызов
валидируется против бандла OpenAPI. Тесты, которые намеренно шлют
невалидный запрос, отключают проверку через `withoutContractValidation()`.

**`RefreshDatabase` для всего, что работает с базой.** Схема тестовой базы
всегда соответствует миграциям, ручные прогоны не нужны.

**Замыкания на верхнем уровне файла Pest не видят `$this` и `test()`.**
Всё, что требует контейнера, принимает его параметром либо живёт в
`beforeEach`.

**Проверки уровня «собрано правильно» имеют смысл.** Порядок middleware
шины, непустота карт, соответствие прав в атрибутах объявленным в конфиге —
всё это ломается тихо, и тест дешевле отладки.

**Сквозные тесты ловят то, что не видят юнит-тесты.** Сериализация и
десериализация пустых метаданных outbox по отдельности были корректны, а
стык между ними не работал.

## Инструменты

**PSR-4 проверяется в CI.** `composer dump-autoload --strict-psr` ловит
несовпадение имени класса и файла — на macOS с нечувствительной к регистру
файловой системой это иначе всплывает только в Linux-контейнере.

**Перед коммитом — `make fix && make qa`.** Pint в `qa` работает в режиме
проверки, исправляет `make fix`.

**Перед завершением этапа — `make fresh`.** Dev-база накапливает состояние,
которого не будет на чистом развёртывании; ошибки порядка миграций иначе
всплывают только в CI или на стенде.
